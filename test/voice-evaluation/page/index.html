Voice evaluation

Speed is not quality. The benchmarks say how fast a voice runs and then throw the audio away — this keeps it, beside the text it was made from, so the judgement can be made by a person with headphones on.

Run

A run is one model at one configuration. Nothing is overwritten, so two can be compared — side by side on A/B, and bar against bar on Charts.

    The same summary, voiced by two runs. Play both, then say which is better — "which of these two?" is a more reliable judgement than scoring one clip out of context, which is why TTS Arena ranks this way and why absolute scores do not survive comparison between experiments.

    Speaking pace, run against run

    Pace decides how many bytes a day costs, because a slower voice says the same words over more seconds. It is host-independent — the model is deterministic, so this figure transfers between machines where wall clock does not.

    This is not a MOS, and must not be reported as one

    ITU-T P.800.2 forbids comparing mean-opinion scores across experiments. P.808 removes outlier raters at |z| ≥ 3.29, which one rater cannot do. TTS Arena needs 100 votes before it will publish a rating at all. This instrument is a within-harness engineering signal — a regression tripwire and a go/no-go — valid only against another run of this same harness, with the same rater, instructions and playback device.

    Four scores, four open questions

    Each closes a gap the CI-runner benchmark left open. Three is the pass mark.

    ScoreThe question it closes
    IntelligibilityCould every word be made out without replaying?
    PronunciationNames, numbers, acronyms. Not a perceptual judgement — the text says what the words are, so this has an objective ground truth and is a placeholder until an ASR round-trip replaces it.
    ProsodyDoes it read like a person reading news, or like a list of words?
    SeamsAre the chunk joins audible? The pipeline splits every summary over forty words, so a seam is an artefact this project creates and therefore one it owns.

    A score has five steps, and no score is not a zero

    Each score is a rail with five stops. Click a stop, click anywhere on the rail to jump to the nearest one, drag the handle, or press 1 to 5 with the rail focused. A rail with no handle has not been scored — it reads "unrated" and counts as nothing, which is a different fact from a 1. The rail was chosen over five numbered boxes because the fill says at a glance how a clip did; the five stops were kept because a listener working through twenty-four clips needs to set an exact value in one action, and a free-moving handle cannot be.

    Follow-the-text is exact between chunks and interpolated within one

    Each chunk is its own inference call, so where it begins in the finished clip is known exactly and costs nothing to record. Within a chunk the highlight is interpolated by character position, not measured. The ONNX export publishes waveform as its only output, so the duration predictor inside the graph cannot be reached; word-level timing would need the model re-exported from PyTorch with pred_dur as a second output. The chunk boundary itself is exact, and it is the one place a seam can be heard.

    Where the scores go

    Nothing leaves this page. Scores persist to this browser's local storage as you work, keyed by run, so judging a second model does not overwrite the first. Download evaluation writes a JSON file that stands alone once the clips are gone, because it copies the run it judged.
